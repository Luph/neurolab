## 0. How this unit is organized

Part VII builds one workbook, the Case P reference model, from a blank file. Chapters 39 to 43 each add sheets and rows in a fixed order; Chapter 44 audits a seeded copy of the finished model; Chapter 45 adds sector modules on Cases T and R and on illustrative assets. Because the seven chapters share one workbook, this file opens with the **Part VII model build map** (Section 0.2): the sheet list, the row map of every sheet with the chapter that builds each block, the formula for the first period column in mathematical notation and in Excel, and the macros. Each chapter brief then cites the rows it builds. Writers must not re-specify rows another chapter builds; they cross-reference them.

### 0.1 Coordination with the modeler and the companion workbook

The modeler agent is building `model/case_p.py`, `model/Case_P_Model.xlsx` and the figure ledgers at the same time as this brief. When this brief was written, `book/model/` held only the three input files; no workbook, Python mirror or ledger existed. Therefore:

1. The row map below is the book's canonical layout. It follows the style sheet (Section 5.4) exactly: sheet order Cover, Inputs, Time, Construction, Operations, Tax, Funding, Debt, Reserves, Waterfall, Financials, Ratios, Returns, Checks, Outputs; column D label, E unit, F constant or scalar result, G row total or check, H and I blank, J the first model period; flags 1 or 0 with the `Flag_` prefix; no range names except `Scenario`; no OFFSET or INDIRECT; costs stored positive and subtracted explicitly.
2. The coordinator should send Section 0.2 to the modeler with the request that `build_excel_p.py` lay out the workbook on this map. If the generated workbook differs, the workbook wins for cell addresses: each writer re-reads the row numbers from `Case_P_Model.xlsx` before quoting a cell, and keeps the sheet names, block order and formulas of this brief. Every row-number difference is reported in the writer's status note.
3. Every Case P number printed in Chapters 39 to 44 is a figure-ledger value cited by ID. This brief never states a Case P model output. Where a chapter needs a figure that has no ID, it is listed in "Case Bible flaws and requests" at the end of this file with a proposed new ID (P-F37 onward, R-F11).
4. Where the Case Bible or the JSON leaves a modeling rule open (for example, how operating years map onto semiannual periods), this brief proposes the rule, marks it "proposed rule", and lists it for the modeler. If the modeler's report adopts a different rule, the writer teaches the modeler's rule.

Equation (39.1), the period end rule:
$$e_t = \begin{cases}\text{end of the month of } s_t & s_t < \text{COD}\\ \min\left(\text{end of June or December after } s_t,\ \text{PPA expiry}\right) & s_t \ge \text{COD}\end{cases}$$
Equation (39.2), operating year (proposed rule, flaw F-01): $\mathrm{OY}_t = \lceil \text{months since COD at } e_t / 12 \rceil$. In the FC base this makes OY1 the eight months May to December 2021 and OY$k$ the calendar year $2020+k$ for $k \ge 2$, so tax years, availability cycle years and maintenance years all align with fiscal years.
